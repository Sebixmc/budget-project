# /specs

Detailed specs for non-trivial features, one file per feature (e.g. `budget-vs-reality.md`). A spec is written **before** implementation and serves as the contract the implementation is held against.

This is a layer of detail below [`/spec.md`](../spec.md): `spec.md` holds the always-current picture and the Open Work Queue (the "tickets"); a file here expands one queue item into purpose, data flow, EARS acceptance criteria, and a test plan when it's big enough to warrant it. Trivial one-file changes don't need one.

See `CLAUDE.md` for authoring rules, `TEMPLATE.md` for the structure, and `proposed-tickets.md` for the loose backlog of not-yet-shaped ideas. Generate a spec with `/specify`.
